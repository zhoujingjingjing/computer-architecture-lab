## 1. 引言

在本实验中，你将扩展实验 1，实现一个包含 L2 缓存和基于 DRAM 的主存的内存层次结构。与实验 1 类似，我们将完整规定 L2 缓存和 DRAM 的逐周期行为。

虽然 L1 缓存与流水线紧密集成，但 L2 缓存与流水线的耦合更松散。在本实验中，我们将保持实验 1 中描述的 L1 缓存语义，但把固定的 L1 缓存缺失延迟 50 个周期替换为可变延迟，该延迟至少涉及 L2 缓存，并可能涉及 DRAM。每当处理器在实验 1 中会开始 50 个周期的 L1 缓存缺失停顿访问时，本实验会改为向存储层次结构发出一个请求。

当数据从 L2 或主存可用时（按下文规定），存储层次结构会向 L1 缓存发出缓存填充通知。如果 L1 缓存仍在等待缺失数据（即没有发生取消），则数据被插入缓存，停顿在下一周期结束。现在我们更详细地规定存储层次结构的确切结构以及请求如何处理。

### 2.1. 统一 L2 缓存

只要两个 L1 缓存（指令或数据）之一发生缺失，就会访问统一 L2 缓存。

**组织。** 它是一个 16 路组相联缓存，大小 256 KB，块大小 32 字节（这意味着缓存有 512 个组）。访问缓存时，组索引用地址的 [13:5] 位。

**MSHR。** L2 缓存有 16 个 MSHR（缺失状态保持寄存器），对于我们简单的顺序流水线来说绰绰有余。对于每次 L2 缓存缺失，L2 缓存分配一个 MSHR 来跟踪该缺失。一个 MSHR 由三个字段组成：(i) 有效位，(ii) 触发缺失的缓存块地址，(iii) 完成位（done bit）。你可以假设所有位初始化为 0。当主存服务完一个 L2 缓存缺失时，它会向 L2 缓存发送完成通知，设置相应 MSHR 中的完成位（即如果 done=1，则该 MSHR 项变为无效且有效位=0）。有效位可用于表示某个 MSHR 项包含一个有效的内存地址（而不是例如 MSHR 中未初始化的地址）。

**访问 L2 缓存。** 假设 L2 缓存有大量端口，访问永远不会被串行化。当一次访存在任一 L1 缓存中缺失时，L2 缓存在与 L1 缓存缺失相同的周期内被立即"探测"（probed）。根据访问在 L2 缓存中是命中还是缺失，处理方式不同。

**L2 缓存命中。** 15 个周期后，L2 缓存向 L1 缓存（指令或数据）发送完成通知。例如，如果一次访问在第 0 个周期于 L1 缓存缺失但在 L2 缓存命中，那么 L1 缓存在第 15 个周期收到完成通知。

**L2 缓存缺失。** L2 缓存立即为该缺失分配一个 MSHR。5 个周期后，L2 缓存向主存发送一个内存请求（这建模 L2 缓存与内存控制器之间的延迟）。当主存服务完该内存请求时，L2 缓存收到完成通知。5 个周期后，取回的缓存块被插入 L2 缓存，相应的 MSHR 被释放（这建模内存控制器与 L2 缓存之间的延迟）。在同一周期，如果流水线因该缓存块而停顿，则 L2 缓存向 L1 缓存发送完成通知。也在同一周期，缓存块被插入 L1 缓存。下一周期，流水线解除停顿。

**管理策略。** 新缓存块被插入 L2 缓存的 MRU 位置。对于 L2 缓存命中，缓存块被提升到 MRU 位置。在同一周期，最多可以发生两次 L2 缓存命中：一次来自取指级，另一次来自访存级。如果它们恰好命中了属于同一组的两个不同缓存块，那么哪个块被提升到 MRU 位置就存在歧义。在这种情况下，我们假设访存级在取指级之前访问 L2 缓存：我们把访存级请求的块提升到 MRU 位置，把访存级请求的块提升到 MRU-1 位置。L2 缓存采用真正的 LRU 替换。

**其他。**

- 假设 L1 和 L2 缓存初始为空。
- 假设处理器上运行的程序从不修改自己的代码（称为自修改代码）：给定缓存块不能同时驻留在两个 L1 缓存中。
- 与 L1 缓存访问不同，L2 缓存访问一旦发起就不能被取消。
- 与实验 1 类似，我们不建模可能从 L1 数据缓存（到 L2 缓存）或 L2 缓存（到主存）发生的脏块换出。当一个新插入的缓存块换出一个脏缓存块时，我们假设该脏缓存块被瞬时写入存储层次结构中紧接着的下一层。此外，这不会引起任何副作用：相应缓存组中缓存块的 LRU 顺序不受影响；在 DRAM 中，总线/组不被占用，行缓冲区状态不变。
- 当 L2 缓存没有剩余空闲 MSHR 时（在我们简单的顺序流水线中不应发生），那么 L1 缓存缺失甚至无法探测 L2 缓存。换句话说，空闲 MSHR 是访问 L2 缓存的先决条件，无论该访问实际上会在 L2 缓存中命中还是缺失。一个被释放的 MSHR 可以在同一周期被重新分配给另一个 L2 缓存缺失。
- 一旦在 MEM 级发生缓存缺失（数据或指令），你可以自由停顿流水线，直到请求从 L2 缓存（命中或缺失）或主存得到服务。但是，如果同时有一个指令缓存缺失和一个来自已在 MEM 级的较旧指令的数据缓存缺失，那么你可以通过为每个缺失分配一个 MSHR 项来服务这两个指令。

> ¹探测（Probing）是指搜索标志（tag）以确定一次访问的命中/缺失状态。

### 2.2. 主存（DRAM）

**组织。** DRAM 系统在单通道上有单个 rank，通道由命令/地址/数据总线组成。该 rank 有 8 个组（bank）。每个组由 64K 行组成，每行 8 KB。访问主存时，组索引用地址的 [7:5] 位，行索引用地址的 [31:16] 位。例如，地址 0x00000000 处的 32 字节缓存块存储在第 0 组的第 0 行。又如，地址 0x00000020 处的 32 字节缓存块存储在第 1 组的第 0 行。

**内存控制器。** 内存控制器把从 L2 缓存收到的内存请求保存在请求队列中。请求队列可以容纳无限数量的内存请求。在每个周期，内存控制器扫描请求队列（包括当前周期到达的内存请求），寻找"可调度"（schedulable）的请求（稍后描述）。如果只有一个可调度请求，内存控制器就为该请求发起 DRAM 访问。如果有多个可调度请求，内存控制器按以下顺序对请求进行优先级排序，这与 FR-FCFS 策略类似：

1. 行缓冲区命中的请求优先于其他请求
2. 较早到达的请求优先于其他请求
3. 来自访存级的请求优先于其他请求

**DRAM 命令与时序。** 一次 DRAM 访问由发给 DRAM 组的一系列命令组成。有四种 DRAM 命令：ACTIVATE（与组/行地址一起发出）、READ/WRITE（与列地址一起发出）和 PRECHARGE（与组地址一起发出）。每条命令占用命令和地址总线 4 个周期。一旦 DRAM 组收到一条命令，它就"忙"100 个周期，不能接受任何其他命令。在收到 READ 或 WRITE 命令后 100 个周期，该组准备好通过数据总线发送/接收一个 32 字节的数据块——该传输占用数据总线 50 个周期。

**行缓冲区状态。** 每个 DRAM 组都有一个行缓冲区。根据组行缓冲区的状态，服务对该组的内存请求需要不同的命令序列。例如，假设一个内存请求需要访问第 0 组的第 0 行。此时，有三种可能的情况：

- **行缓冲区命中**：第 0 行已经在行缓冲区中
- **行缓冲区缺失**：相应组的行缓冲区中没有加载任何行
- **行缓冲区冲突**：相应组的行缓冲区中加载的是不同于第 0 行的行

下表总结了三种情况各自所需的命令序列。

| 场景 | 命令（延迟） |
|---|---|
| 行缓冲区命中 | READ/WRITE |
| 行缓冲区缺失 | ACTIVATE, READ/WRITE |
| 行缓冲区冲突 | PRECHARGE, ACTIVATE, READ/WRITE |

**"可调度"请求。** 当内存请求的所有命令都能在命令/地址/数据总线以及组上无冲突地发出时（在命令要发出和相应数据预期到达的周期），该内存请求被定义为可调度。例如，在第 0 个周期，对行缓冲区已关闭的组的请求是可调度的，当且仅当满足以下所有条件：

1. 命令和地址总线在第 0、1、2、3、100、101、102 和 103 周期空闲
2. 数据总线在第 200–249 周期空闲
3. 组在第 0–99 和 100–199 周期空闲

首先，命令/地址总线在第 0、1、2、3、100、101、102、103 周期空闲。其次，数据总线在第 200–249 周期空闲。第三，组在第 0–99 和 100–199 周期空闲。

**其他假设与策略。**

- 假设所有组的行缓冲区初始为关闭状态，即任何行缓冲区中都没有行。
- 内存控制器遵循开放行策略（open row policy），即一旦一行被打开，除非另一个已调度的请求需要关闭该行以访问同一组中的另一行，否则它不会被关闭。

### 5.3. 研究时序模拟器

请详细研究 pipe.c 和 pipe.h。

模拟器将每个流水线级建模为一个独立的函数——例如 pipe_stage_fetch()。模拟器将流水线的状态建模为一组指向 Pipe_Op 结构（在 pipe.h 中定义）的指针。每个 Pipe_Op 通过存储模拟器所需的、关于该指令的所有必要信息，来表示流水线中的一条指令。一个 Pipe_Op 结构在指令被取指时分配。然后它流经流水线，最终到达最后一级（写回），指令完成后在此释放。具体来说，每一级从前一级接收一个 Pipe_Op，处理该 Pipe_Op，并将其传给下一级。模拟器通过停止 Pipe_Op 结构的流动来建模流水线停顿，通过在各个级释放 Pipe_Op 结构来建模流水线冲刷。
